# 05-必填驗證與送出

## 目的

在將資料送出前，確保系統遵守法規與業務規則，避免缺漏必填欄位造成錯誤提交。這個階段的核心是：

- 驗證法規必填欄位是否完整
- 阻止缺少必要資料的送出
- 提供清楚提示與修正路徑
- 在條件成立時允許進行送出確認

## 進入條件

- 使用者已完成欄位審核
- 欄位值已更新至最終草稿狀態
- 使用者準備執行送出前驗證

## 完成條件

- 系統已驗證必填欄位是否完整
- 若缺填，使用者被阻止送出並看到具體提示
- 若無缺填，使用者可進行送出確認
- 送出動作只有在條件符合時才被允許

## 主要行為

### 1. 必填欄位驗證

第一版規定的法規必填欄位為：

- 品名
- 有效日期
- 廠商名稱

系統在送出前必須檢查這三者是否已填寫且有效。

### 2. 阻擋送出

若任一必填欄位缺漏，系統應：

- 阻止提交
- 顯示對應錯誤欄位
- 引導使用者回到審核頁面補齊
- 不讓使用者以為已送出成功

### 3. 送出確認

當必填欄位皆已完整：

- 顯示確認畫面或確認對話框
- 讓使用者再次確認提交內容
- 可點選「確認送出」

### 4. 送出執行

- 提交後系統進入送出中狀態
- 如送出成功，轉至完成頁面
- 如送出失敗，顯示錯誤並允許重試或回到編輯狀態

## 必要支線

### 支線 A：必填欄位缺漏

- 系統不可允許送出
- 必須清楚指出缺漏項目
- 使用者需回到審核區修正

### 支線 B：送出失敗

- 可能因網路、後端錯誤或服務異常而失敗
- 系統需保留使用者可恢復的錯誤狀態
- 使用者可重試或回到編輯

## 驗收條件

1. 品名、有效日期、廠商名稱任一缺漏時，不能送出。
2. 缺漏時會明確提示哪個欄位不完整。
3. 使用者能回到審核畫面補齊資料。
4. 必填欄位齊全後，送出確認可正常啟動。
5. 送出中狀態明確，不會讓使用者誤判已完成。
6. 送出失敗時，畫面仍可恢復至可處理狀態。

## 測試

### 1. 必填欄位缺漏測試

- 故意空白品名、有效日期或廠商名稱
- 期望：送出按鈕被禁用，並提示缺漏欄位

### 2. 補齊後送出測試

- 補上缺漏欄位後重試送出
- 期望：系統允許進入確認與送出流程

### 3. 確認送出測試

- 點擊確認送出
- 期望：顯示送出中，且之後進入完成或失敗狀態

### 4. 送出失敗測試

- 模擬後端 4xx / 5xx 或網路錯誤
- 期望：畫面顯示失敗，不會卡住，也可重試

## 介面與約束建議

- 必填欄位應在表單中做高可見性提示
- 錯誤訊息應以欄位為單位對應，避免泛泛說明
- 送出前確認步驟可以簡單但明確，避免誤送
- 若資料曾因失敗而未送出，應保留已填內容供再次修正

## 交付標準

此階段的最低交付要求為：

- 必填欄位有驗證邏輯
- 缺漏時不能送出
- 送出前有確認步驟
- 失敗時可恢復且重試

達成後即可進入「完成與錯誤收尾」流程。
