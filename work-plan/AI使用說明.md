# AI 使用說明

## 目的

本文件用來說明本專案開發過程中如何使用 AI / agent 輔助需求分析、工作規劃、spec 拆分與實作整理。

這不是實際會被 Copilot 或其他工具自動讀取的 agent skill，也不是執行用設定檔，而是交付時讓 reviewer 了解開發方式與主要約束的說明文件。

## 使用 AI 的範圍

本專案使用 AI 輔助以下工作：

- 分析實作題需求與使用者流程。
- 建立以 happy path 為主的工作計畫。
- 將主流程拆成後續可撰寫的 spec。
- 協助整理必要支線，例如解析失敗、取消解析、必填缺漏與多候選答案。
- 協助建立測試情境與驗收條件。
- 協助檢查 README 是否回答題目要求。
- 協助產生部分程式碼草稿，後續由我人工檢查與調整。

## AI 協作方式

本專案開發過程中，我會使用 matt agent skill 協助需求拆解、工作計畫、spec 整理與部分程式碼草稿產生。

產品流程與功能需求會以 `工作計畫書.md` 及後續各流程 spec 為準。這份文件不重複定義完整產品規格，只說明 AI / agent 的使用方式與我對程式碼品質的要求。

## Coding 規格

AI 協助產生或修改程式碼時，需要遵守以下原則：

- 遵守 clean code 原則。
- 使用有意義的變數、函式與元件命名。
- 保持函式責任單一，避免把多個流程混在一起。
- 優先使用簡單、可讀、可測試的寫法。
- 避免過早抽象或建立不必要的共用層。
- 不為了減少行數犧牲可讀性。
- 錯誤狀態與 loading 狀態需要明確處理。
- 不修改後端提供的 `server.py`。
- 若需求不清楚，需標記為假設，而不是直接寫死在程式裡。

## 我會人工確認的部分

AI 產出後，我會人工確認以下內容：

- 是否符合題目需求。
- 是否過度設計或偏離第一版範圍。
- 使用者是否能知道目前處理到哪裡。
- 使用者是否能快速找到需要人工判斷的欄位。
- 必填欄位驗證是否真的能防止誤送。
- 解析失敗或取消時是否會卡在 loading。
- 欄位分組是否保留文件脈絡與原始順序。
- 測試是否能保護關鍵流程，而不是只測畫面存在。
- README 是否清楚說明取捨、驗證方式、AI 使用與不確定處。

## 不做成真正 Skill 的原因

目前這份文件的目的只是說明 AI 使用方式與 coding 原則，不需要被 Copilot 自動載入，也不需要作為 slash command 或 workflow skill 使用。

若後續「建立 spec」或「根據 spec 建立測試」變成需要重複執行的固定流程，才會考慮另外整理成真正的 agent skill。

## 目前不確定的部分

以下項目需要在實作或閱讀 mock 後端 API 後再確認：

- 後端是否支援真正取消解析，或前端只能停止等待。
- 後端是否會提供解析進度，或只能由前端顯示階段型進度。
- 解析結果是否一定包含頁碼或來源資訊。
- 多候選答案是否有排序、信心分數或推薦值。
- 非必填欄位尚未確認時，是否仍允許送出。
