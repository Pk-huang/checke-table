# 文件解析審核流程工作計畫書

## 目的

先完成一條可運作的主流程：使用者選擇文件，送到後端解析，取得欄位結果後進行審核，補齊必填欄位並送出。

這份計畫書只描述第一版的開發順序與共同限制。各流程的細節、支線情境與測試會放在各自的 spec 文件中。

## 第一版主流程

```mermaid
flowchart LR
    A[選擇文件] --> B[上傳文件]
    B --> C[等待解析]
    C --> D[取得解析結果]
    D --> E[審核欄位]
    E --> F[必填驗證]
    F --> G[送出確認]
    G --> H[完成]
```

## Happy Path 開發順序

| 順序 | 流程 | 目的 | 最低完成標準 |
|---|---|---|---|
| 1 | 開始與上傳 | 讓使用者選擇文件並開始處理 | 顯示檔名與上傳狀態，成功後進入解析 |
| 2 | 等待解析 | 避免使用者面對空白等待 | 顯示解析中狀態與目前處理階段 |
| 3 | 解析結果整理 | 將後端結果轉成前端可審核資料 | 欄位依群組整理，同組內保留原始順序 |
| 4 | 欄位審核 | 讓使用者檢查、修改與確認欄位 | 欄位可編輯，低把握度與多候選欄位可辨識 |
| 5 | 必填驗證與送出 | 避免缺少法規必填資料時送出 | 品名、有效日期、廠商名稱缺漏時阻擋送出 |
| 6 | 完成與錯誤收尾 | 讓流程有明確結束狀態 | 送出成功後顯示完成；失敗時可回到可處理狀態 |

## 必要條件限制

第一版開發時，每個流程都需要遵守以下條件：

- 解析期間不能讓使用者面對空白畫面。
- 後端解析失敗時，畫面不能永久停在 loading。
- 使用者在解析中必須可以取消或離開等待狀態。
- 抓出的欄位需要能確認與修改。
- 低把握度欄位需要被明確標示，方便人工檢查。
- 有多個候選答案的欄位，需要能選擇候選值或自行輸入。
- 欄位需要依群組整理：基本資料、營養標示、檢驗結果、廠商資訊。
- 同一群組內應保留文件中出現的原始順序。
- 法規必填欄位缺漏時不能送出：品名、有效日期、廠商名稱。
- 解析結果需要保留文件脈絡，例如頁碼或來源資訊，方便回頭確認。

## 支線處理方式

第一版的開發順序以 happy path 為主，支線不另外作為主流程展開，而是放進對應流程的 spec 中處理。

| 支線情境 | 放入的 spec |
|---|---|
| 沒有選擇文件 | `01-開始與上傳.md` |
| 檔案格式或大小不符合預期 | `01-開始與上傳.md` |
| 上傳失敗 | `01-開始與上傳.md` |
| 解析中取消 | `02-等待解析.md` |
| 解析失敗 | `02-等待解析.md` |
| 解析逾時或等待過久 | `02-等待解析.md` |
| 沒有解析到任何欄位 | `03-解析結果整理.md` |
| 欄位群組混雜 | `03-解析結果整理.md` |
| 低把握度欄位 | `04-欄位審核.md` |
| 多候選答案 | `04-欄位審核.md` |
| 欄位數量很多 | `04-欄位審核.md` |
| 必填欄位缺漏 | `05-必填驗證與送出.md` |
| 送出失敗 | `06-完成與錯誤收尾.md` |

## 預計建立的 Spec

第一版先建立以下 spec，避免文件切得過細：

1. `01-開始與上傳.md`
2. `02-等待解析.md`
3. `03-解析結果整理.md`
4. `04-欄位審核.md`
5. `05-必填驗證與送出.md`
6. `06-完成與錯誤收尾.md`

每份 spec 需包含：

- 目的
- 進入條件
- 完成條件
- 主要行為
- 必要支線
- 驗收條件
- 測試

## 第一版測試策略

測試不追求數量，而是優先保護最容易造成錯誤結果的流程。

優先測試項目：

1. 上傳成功後會進入解析中。
2. 解析中會顯示明確狀態，不是空白畫面。
3. 解析成功後能依群組顯示欄位。
4. 低把握度與多候選欄位能被使用者辨識。
5. 必填欄位缺漏時不能送出。
6. 補齊必填欄位後可以進入送出確認。
7. 解析失敗時不會永久 loading。
8. 解析中取消後不會被誤當成成功結果。

## 暫不優先處理

以下項目先不列入第一版必要範圍，若時間足夠再補：

- 草稿保存與恢復。
- 精準 PDF 文字框選或高亮。
- 批次上傳。
- 多人協作審核。
- 完整無障礙覆蓋。
- 大量欄位的虛擬列表最佳化。
- 詳細審核歷史與版本比較。

## 取捨說明

第一版先用 happy path 排開發順序，是為了快速建立一條可驗證的端到端流程。支線情境仍會納入，但會放在對應 spec 裡，確保主計畫簡潔，同時不忽略會造成卡住、誤送或無法判斷狀態的風險。
